# CLAUDE.md — Stock Analysis Apps: Operating Manual

Monorepo of Indian stock-market analysis tools. Apps scrape Screener.in, run LLM pipelines (OpenAI / Gemini / Claude) that score companies 0–100, and visualize results. Windows 11, Python 3.12, venv at `.venv/`, API keys in `.env` (`OPENAI_API_KEY`, `GOOGLE_API_KEY`, optional `ANTHROPIC_API_KEY`).

Every folder has its own CLAUDE.md with architecture detail — read the one for the folder you're editing. THIS file is the cross-cutting rulebook: the things that break silently, cost API money, or corrupt scores when done wrong.

## Map

| Path | What it is | Role |
|---|---|---|
| `Full App/` | FastAPI backend + single-page frontend (`frontend/index.html`: Tailwind + Alpine.js + Plotly) | **Primary app.** Canonical home of prompts (`backend/services/prompts.py`) and shared services |
| `FullScreener/` | Streamlit, single file (`Fullscreener_app.py`) | Sector pipeline (8 phases) — standalone twin of `sector_pipeline.py` |
| `individual/` | Streamlit, single file (`IndividualStockApp.py`) + `transcript_scorer.py` (RAG concall scorer) | Individual pipeline (8 steps) — standalone twin of `individual_pipeline.py` |
| `Visualizations/` | 2 Streamlit dashboards | Read-only views over output data; origin of the extraction/classification logic now also in `individual_service.py` / `sector_service.py` |
| `MyHoldings/` | Streamlit portfolio app | Imports Full App services via `sys.path` — service signature changes break it |
| `Sector/`, `Individual_Stocks/`, `scores.json` | **Machine-generated output data** | Never hand-edit; regenerated by pipelines/dashboards |
| `models.json` | LLM model IDs + `model_options` list | The ONLY place model IDs live; `config.py` hard-fails on missing keys |
| `prompts/` | Markdown docs of every prompt | Third copy of prompt content — update when prompts change |
| `ClaudeAnalysis/` | HTML reports + `registry.json` from the `/analyze-stock` skill | Skill-owned; upsert registry, never overwrite wholesale |

**Pipelines in one line each.** Sector: scrape sector URL → per-company financial extraction (Phase 5, file-cached) → 0–100 score (Phase 6, file-cached) → JSON (Phase 7, resumable via `progress.json`) → `{sector}.csv` + `{sector}.json`. Individual: scrape company → extract text → structured JSON → sector KPI list → KPI values (Gemini Search, fallback = calculate) → final analysis + score (`Individual_Stocks/{Company}.txt`) → Walk the Talk (Gemini Search, fallback = training-data synthesis) → concall credibility score.

## Law #1 — Everything Important Exists in More Than One Place

The Streamlit apps and the Full App are parallel implementations that must behave identically. **Any change to a prompt, a threshold, a regex, or pipeline step logic must land in every copy in the same commit.** This is the single most common way this repo gets broken. The copy map:

| Artifact | Copies (canonical first) |
|---|---|
| Individual pipeline system prompts (7) | `Full App/backend/services/prompts.py` → `individual/IndividualStockApp.py` → `prompts/individual_pipeline.md`. Note the name shift: `*_SCREENER_IND` / `*_JSON_IND` in prompts.py = `*_SCREENER` / `*_JSON` in the Streamlit app |
| Sector pipeline system prompts (3) | `prompts.py` → `FullScreener/Fullscreener_app.py` → `prompts/sector_pipeline.md` |
| User-prompt generator functions | `prompts.py` → same-named functions in each Streamlit app |
| Walk the Talk prompt | THREE variants: `user_prompt_walkthetalk` (training-data), `user_prompt_walkthetalk_search` (grounded), and the RAG variant in `individual/transcript_scorer.py`. A guard added to one usually belongs in all three |
| Score extraction regexes | `Full App/backend/services/individual_service.py` ↔ `Visualizations/Individualscoreapp.py` |
| Tier (80/60/40) & signal (75/60/50) thresholds | `individual_service.py`, `Individualscoreapp.py`, `Full App/backend/config.py` (`TIER_THRESHOLDS`), `.claude/skills/analyze-stock/skill.md` |
| Financial scoring weights 40/20/15/15/10 | `DEFAULT_SYSTEM_PROMPT_FINAL` + `create_user_prompt_final` (both copies) + `analyze-stock` skill |
| Concall weights 30/25/20/15/10 + achievement bands (>105/95/85) | `DEFAULT_SYSTEM_PROMPT_CONCALL_SCORE` (both copies) + `transcript_scorer.py` + `analyze-stock` skill |
| `floor(max/10)*10` CSV combiner | `sector_service.py` ↔ `Visualizations/ScoreVisualApp.py` |
| Step/phase logic | `individual_pipeline.py` ↔ `IndividualStockApp.py`; `sector_pipeline.py` ↔ `Fullscreener_app.py` |

Run `/prompt-sync audit` before and after touching any of these. Sync direction is always **prompts.py → Streamlit copies** (prompts.py is canonical and usually ahead).

## Conventions

Observed in this repo — follow them:

- **Analysis logic lives in prompts, not code.** If a score is wrong, the fix is almost always a prompt guard, not Python. Code changes are for plumbing (caching, dispatch, endpoints, UI).
- **Prompt engineering style**: guards are added as loud, explicit blocks — `**CRITICAL ... (non-negotiable)**`, worked EXAMPLE lines, SELF-CHECK instructions, exact output tables with fixed row labels. New guards follow this style and are **appended**, not woven into existing text.
- **Single-file Streamlit apps** with numbered section comments; all widget state keys initialized in a `DEFAULTS` dict.
- **Caching by file existence**: pipelines skip any company whose output file already exists. Deleting the file IS the invalidation mechanism.
- **Model IDs** come from `models.json`; code refers to aliases (`gemini-flash`, `openai`, `claude-sonnet`…) resolved in `llm_service.py` / app-level `llm()` dispatchers.
- **Rate limiting**: `time.sleep(1)` between screener.in requests; max 100 LLM calls per sector Phase-5 run. Both are deliberate.
- **Commit style**: imperative subject; body explains what + why; when a scoring behavior changed, the body records verification evidence (e.g. "Verified: MapMyIndia score corrected from 83 to 52"); `Co-Authored-By: Claude <model> <noreply@anthropic.com>` trailer.
- **Output data is committed** — sector CSVs/txt change as pipelines run; keep data churn in separate commits from code changes.

Added rules — follow these too:

- **Parity audit is part of done** for any prompt/threshold/regex change (`/prompt-sync audit` → the edited artifact reports IN SYNC).
- **Every prompt change updates `prompts/*.md`** in the same commit, or explicitly notes the doc is stale.
- **Score-impact evidence in the commit body** whenever a change can move scores: name one company, its before score, its after score.
- **Prefer the Full App API for programmatic verification** (`curl` against `localhost:8000`); Streamlit apps are for interactive use only.

## The Traps — named mistakes and the rule that prevents each

1. **The Lone-Copy Edit.** Editing a prompt in `prompts.py` and forgetting `IndividualStockApp.py` (or vice-versa). Both apps keep "working", scores quietly diverge, and the bug is discovered weeks later. → *Rule: consult the Law #1 copy map before any edit; all copies in one commit; `/prompt-sync audit` must pass.*
2. **The Regex "Cleanup".** The extraction patterns in `individual_service.py` / `Individualscoreapp.py` look wrong — e.g. `(?:dYY.|dY..?)` appears to be a typo. It is not: it matches cp1252-mojibake'd emoji that exist in real output files. → *Rule: NEVER modify or "simplify" an existing extraction pass. To support a new LLM output format, append a new pass at the END, then dry-run against every existing file in `Individual_Stocks/` — zero previously-extracted values may change.*
3. **The Cache Mirage.** Changing a prompt, rerunning the pipeline, concluding "no effect" — because Step 1 / Phases 5–6 loaded cached files and never called the LLM. → *Rule: after a prompt change, delete the affected cache files (or answer `delete` at the pipeline's cache prompt) before the verification run. Step 1 cache lives in `Sector/{sub_sector}/{Company}.txt`, results in `Individual_Stocks/{Company}*.txt`.*
4. **The Free Test Run.** Running a pipeline "just to test". A sector run is up to 100 LLM calls plus 30–40 scraped pages at 1 req/sec; an individual run hits Gemini Pro with search grounding twice. → *Rule: never start a pipeline the user didn't ask for. Verify with offline checks (imports, extraction dry-runs, endpoint smoke tests). When the user wants behavior verified, one individual-company run is the accepted cost — use `/rerun-stock`.*
5. **The Underscore Landmine.** File classification in `Individual_Stocks/` is name-driven: a `.txt` with no underscore in the stem = financial analysis; `_concall.txt` and `_concall_score.txt` are the only valid suffixes. A helpfully-named `{Company}_backup.txt` or `{Company}_v2.txt` corrupts the dashboards. → *Rule: never write any other filename pattern into `Individual_Stocks/`. Scratch files go in the scratchpad.*
6. **The Helpful Threshold Tweak.** "Improving" tier cutoffs, signal rules, scoring weights, achievement bands, or the `floor(max/10)*10` filter. These are frozen constants replicated across 4+ files, and all historical data was scored against them. → *Rule: never change them on your own judgment. If the user asks, confirm they understand old scores stay on the old scale, then change every copy in the map.*
7. **The Guard-Block Deletion.** "Tidying" a prompt by removing verbose blocks: TODAY'S DATE, CRITICAL DATA INSTRUCTION (FY25/FY26 are actuals, not projections), Revenue-from-Operations-not-Total-Income, Guidance Period Assignment, PERIOD MISMATCH integrity check, the fixed 5-dimension score table, Data Confidence banners, the 100 KB size guards, `concall_source` flag plumbing. Each exists because of a specific observed LLM failure recorded in git history. → *Rule: prompt edits are additive. Removing or weakening any guard requires the user's explicit OK.*
8. **The Hardcoded Model ID.** Writing `"gemini-2.5-flash"` in code, or adding a model alias in one dispatcher only. → *Rule: model IDs go in `models.json` only. Adding a model = new key in `models.json` + `model_options` + match-arm in `llm_service.llm()` AND both Streamlit `llm()` dispatchers + `check_api_status` list.*
9. **The Encoding "Fix".** Output files contain mojibake (`dYY'`, `â€"`) from historical cp1252 writes; the extraction regexes compensate. Bulk-fixing files, or writing without `encoding="utf-8"`, breaks extraction. → *Rule: leave existing data files byte-for-byte alone; always pass `encoding="utf-8"` when writing (CSV: `utf-8-sig`); never trust console rendering of emoji on Windows.*
10. **The Session-State Ghost.** Adding a Streamlit widget or state key without registering it in the app's `DEFAULTS` dict — works until the next rerun/reset, then KeyErrors or silently reverts. → *Rule: every new `st.session_state` key gets a `DEFAULTS` entry.*
11. **The Hand-Edited Output.** "Fixing" a wrong dashboard number by editing `scores.json`, `Sector_Combined.csv`, or a `.txt` report. All are overwritten on next run. → *Rule: fix upstream (prompt or extraction pass), then regenerate. To trace a wrong number: file → extraction pass → `scores.json` → API/dashboard; find the first divergent link and report it.*
12. **The Frontend Key Guess.** `frontend/index.html` (~1900 lines, Alpine.js) reads router JSON keys verbatim. Renaming a key in a router silently blanks a UI panel. → *Rule: grep `index.html` for every JSON key you touch in a router response, and vice-versa.*

## Quality Bar — checkable criteria per deliverable

**A prompt change is done when:**
- [ ] Text is identical (whitespace-normalized) in `prompts.py` and the matching Streamlit constant — `/prompt-sync audit` reports IN SYNC for it
- [ ] All applicable Walk-the-Talk variants updated (see Law #1 row)
- [ ] `prompts/individual_pipeline.md` or `prompts/sector_pipeline.md` updated
- [ ] Every guard block from Trap #7 still present in the final text
- [ ] If scoring semantics changed: one known company rerun with cache deleted; new file's score extracts to a number; before → after score recorded in the commit body

**A Full App backend change is done when:**
- [ ] `python -m uvicorn backend.main:app --port 8000` boots with zero traceback (run from `Full App/` with the venv)
- [ ] `curl -s localhost:8000/api/health` returns 200
- [ ] Each touched endpoint returns valid JSON whose keys match what `frontend/index.html` reads
- [ ] No new packages added without the user's OK

**A Streamlit change is done when:**
- [ ] The app boots headless without exception (`streamlit run <app> --server.headless true`, check the first seconds of log, then kill)
- [ ] New state keys exist in `DEFAULTS`
- [ ] If the change touched pipeline/classification logic: the Full App twin got the same change

**An extraction/classification change is done when:**
- [ ] Dry-run over every file in `Individual_Stocks/` (or every `_Score.txt` for sector): extracted-count ≥ before, and no previously-extracted value changed
- [ ] Applied to both copies (`individual_service.py` + `Individualscoreapp.py`)

**Regenerated data is done when:**
- [ ] `scores.json` parses and has both top-level keys (`overall_scores`, `credibility_scores`)
- [ ] `Sector_Combined.csv` has exactly `company,score,Sector,url` and every row's score ≥ `floor(its sector's max /10)*10`

**A commit is done when:**
- [ ] Imperative subject; body = what + why + verification evidence
- [ ] All sibling copies of the change are in the SAME commit
- [ ] `Co-Authored-By: Claude <model> <noreply@anthropic.com>` trailer
- [ ] No unrelated output-data churn mixed in

## When Uncertain — exact escalation rules

**Always stop and ask the user before:** changing scoring weights / tier / signal thresholds / achievement bands / floor filter; removing or weakening a prompt guard block; deleting anything in `Sector/` or `Individual_Stocks/` beyond the specific company being rerun at the user's request; editing `.env` or `models.json` model IDs; adding a dependency; starting a sector pipeline run (cost); raising the 100-call or 100 KB safety limits.

**Proceed without asking when:** adding a new extraction pass (append-only, dry-run proven); appending a prompt guard the user requested plus syncing its copies; plumbing fixes with green smoke tests; updating docs/CLAUDE.md files to match reality.

### Sector pipeline (FullScreener / `sector_pipeline.py`)
- Scraper returns 0 company links or page count looks wrong → screener.in markup likely changed. Save the fetched HTML as evidence, report which selector broke. Do NOT speculatively rewrite the `Website` class.
- A company's score won't extract from `_Score.txt` → inspect the file; if the LLM used a new format, append a regex pass; never edit existing passes.
- Sector has >100 companies → don't raise the cap; tell the user Phase 5 will need multiple runs (caching makes reruns resume).
- A sector folder name mismatches its CSV name → report it; folder names come from screener page titles and may contain `&` etc. Don't rename data folders.

### Individual pipeline (`individual/` / `individual_pipeline.py`)
- Step 1 output > 100 KB → the guard aborts by design. Diagnose the scrape (nav junk, peer tables leaking into `get_financial_text()`); don't raise the limit.
- Gemini Search fails on Step 4/6 → fallbacks are intentional. Never remove the `concall_source` flag, the `_SYNTHESIS_DISCLAIMER`, or the LOW/HIGH confidence banner in `prompt_concall_score` — a credibility score without its grounding provenance is worse than no score.
- User says a concall score "looks wrong" → FIRST check whether `{Company}_concall.txt` contains the synthesis disclaimer (un-grounded run). If so, the fix is rerunning with search grounding, not editing prompts.
- Score wrong in a way that smells like the LLM misread data (projection vs actual, wrong FY row, Total Income as revenue) → strengthen the specific existing guard block additively; verify per the prompt-change quality bar.
- Unsure whether a fix belongs in code or prompt → prompt.

### Visualizations / Full App data layer
- Dashboard number wrong → trace file → regex → `scores.json` → endpoint; report the first divergent link. Never patch downstream.
- Company missing from a dashboard → usually extraction returned `None` (new format) or a filename violates the underscore convention. Diagnose with `/data-doctor`, don't guess.

### `/analyze-stock` skill runs
- It is read-only w.r.t. `Apps_link` pipelines: writes only to `ClaudeAnalysis/`. Keep its scoring weights/signal table in sync when the user changes pipeline scoring (Law #1).

## Environment & Commands

```powershell
# venv python — use for ALL scripts (never system python)
.venv\Scripts\python.exe

# Full App (primary)
cd "Full App"; ..\.venv\Scripts\python.exe -m uvicorn backend.main:app --host 0.0.0.0 --port 8000
curl -s http://localhost:8000/api/health

# Streamlit apps (each also has a run.bat)
.venv\Scripts\activate
streamlit run individual\IndividualStockApp.py
streamlit run FullScreener\Fullscreener_app.py
streamlit run Visualizations\ScoreVisualApp.py      # sector dashboard
streamlit run Visualizations\Individualscoreapp.py  # individual dashboard
```

Data-path override for Full App: `STOCK_HUB_ROOT` env var. LLM defaults per step live in `individual_pipeline.py` (`gemini-flash`/`gemini-pro` mix) — don't change defaults silently.

## Project Skills

- `/prompt-sync` — audit or apply prompt/threshold changes across every copy in the Law #1 map. Run `audit` mode before claiming any sync-sensitive change done.
- `/rerun-stock <company|url>` — safe cache-invalidating rerun of one company via the Full App API, with before/after score comparison. The standard way to verify prompt changes.
- `/data-doctor` — full health audit of `Individual_Stocks/`, `Sector/`, `scores.json`, `Sector_Combined.csv`: extraction failures, missing companions, un-grounded concalls, stale combined rows.
- `/analyze-stock <companies>` — parallel Claude research agents produce standalone HTML reports in `ClaudeAnalysis/` (no pipeline involvement).
